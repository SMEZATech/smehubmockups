Dev note, confirmation (Workstreams A, B, C). Reached after a successful registration (event-register.html). ?wa=1 when WhatsApp was ticked, ?member=1 for a member; the state tabs above are a preview control. The page is noindex and per registrant (the URL carries a signed registration token, never the email).

Time: always SAST first; the visitor's local time is computed in the browser with Intl and only shown when it differs (try ?tz=Europe/London). Store times as UTC with the event timezone Africa/Johannesburg; schema and .ics carry +02:00 / TZID.

Calendar: Google calendar.google.com/calendar/render?action=TEMPLATE, Outlook outlook.live.com/calendar/0/deeplink/compose, Apple = .ics (UID event-ID@smesouthafrica.co.za, same file attached to the email). Location = the event page URL, never the join link. Do not copy the old shortcode bug (SAST string read as UTC, labelled Z).

Join link: personal, on our domain (/e/j/<token>), redirects to the webinar link from 30 minutes before start and records the click. Never printed on this page. Vendor name never shown.

WhatsApp: approved templates only (event_confirmation, event_reminder_1d, event_link_1h, event_live_now, event_replay_ready), sent only when the WhatsApp consent entry is granted, every template ends with the STOP line; STOP writes a withdrawal to the consent ledger. Sender sits behind an off switch and the Comms Governor (transactional class).

Invite link: ?ref= code of this registrant, stored on the new registration. dataLayer: event_add_to_calendar (calendar), event_share (network), no personal data.
